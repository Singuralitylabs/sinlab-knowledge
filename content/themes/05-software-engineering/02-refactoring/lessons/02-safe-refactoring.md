# 安全なリファクタリングの進め方

リファクタリングの怖さは「直したつもりが、こっそり振る舞いを変えてしまう」ことにあります。本ページでは、振る舞いを壊さずにリファクタリングを進めるための 4 つの安全装置——**テスト・小さなステップ・Git・差分の確認**——を解説します。

## このページで学べること

- リファクタリングの **安全網（テスト）** を先に用意する理由
- **小さなステップ** で進めることの重要性
- **Git** をロールバック可能な安全装置として使う
- 変更を **差分で確認** する

## 安全装置その1：テストで振る舞いを固定する

リファクタリングの大前提は **「振る舞いを変えていないと確認できること」** です。それを保証するのがテストです。

```text
1. リファクタリング対象の現在の振る舞いを、テストで固める
2. テストが通る（＝今の動作を正しく捕捉している）ことを確認
3. リファクタリングを実行
4. テストが通ったまま ＝ 振る舞いは保たれている
```

対象にテストがない場合は、**リファクタリング前にまずテストを書く**のが鉄則です。現在の振る舞いをそのまま固定するテストは **特性テスト（characterization test）** と呼ばれます。

> [!IMPORTANT]
> テストのないコードのリファクタリングは「安全網なしの綱渡り」です。「まずテスト、それからリファクタリング」の順序を崩さないでください。

## 安全装置その2：小さなステップで進める

一度に大きく書き換えると、問題が起きたときに「どの変更が原因か」を特定できなくなります。リファクタリングは **小さな変更の積み重ね** で進めます。

| 進め方 | リスク | 問題発生時の対応 |
| --- | --- | --- |
| 一括で大改造 | 高い | どこが原因か特定困難。全部を疑う羽目に |
| 小さなステップ | 低い | 直前のステップを戻すだけで済む |

各ステップの後でテストを実行し、**緑（成功）を保ったまま次へ進む**——これが安全なリズムです。

> [!TIP]
> 「リファクタリングのステップ」と「機能変更」は決して混ぜないこと。1 つのステップは「振る舞いを変えない変更だけ」で構成します。途中で「ついでに機能も直したい」と思ったら、それは別の作業として切り出します。

## 安全装置その3：Gitで戻れるようにする

Git は強力な安全装置です。各ステップを **小さくコミット**しておけば、問題が起きても直前の状態に即座に戻せます。

```bash
# リファクタリング前の状態をコミット（戻れる起点を作る）
git add -A && git commit -m "refactor前の状態"

# 1ステップ実行 → テスト → 問題なければコミット
npm test && git commit -am "refactor: 重複していたバリデーションを共通関数に抽出"

# 問題が出たら戻す
git restore .            # まだコミットしていない変更を破棄（最新コミットの状態に戻る）
git reset --hard HEAD~1  # 直前のコミットごと取り消す（コミット済みの場合）
```

> [!NOTE]
> リファクタリングは作業用ブランチで進め、main へ直接コミットしないのが安全です。「いつでも戻せる」と分かっていれば、安心して大胆な改善に踏み込めます。

## 安全装置その4：差分を確認する

変更したら、**diff を必ず自分の目で確認**します。「テストが通ったから OK」と差分を読まずに進めるのは危険です。テストが捕捉していない振る舞いの変化が紛れていることがあります。

確認すべきポイント：

- **振る舞いを変える変更が混じっていないか**（条件式の変更、デフォルト値の変更など）
- **スコープ外の変更が含まれていないか**（意図していない箇所の書き換え）
- **削除してよいコードか**（実は使われている処理を消していないか）

> [!CAUTION]
> リファクタリングのつもりで、境界条件の `<` を `<=` に変えるなど、**気づかぬうちに振る舞いを変えてしまう**ことがあります。差分の確認は、この種の事故を捕まえる最後の砦です。テストと目視の両方を通しましょう。

## 安全なリファクタリングの手順まとめ

1. 作業用ブランチを切り、現状をコミット（戻れる起点）
2. 対象にテストがなければ、現在の振る舞いを固定するテストを書く
3. リファクタリングを **小さなステップ** に分割
4. 1 ステップ実行 → テスト実行 → 差分確認 → コミット
5. 3〜4 を繰り返し、目的を達成したら完了

## まとめ

- リファクタリングの大前提は **テストで振る舞いを固定** すること。なければ先に書く
- **小さなステップ**で進め、各ステップ後にテストを通して緑を保つ
- **Git でこまめにコミット**し、いつでも戻れるセーブポイントを作る
- 変更は **diff を必ず確認**し、テストが捕捉しない振る舞いの変化を捕まえる
- テスト・小さなステップ・Git・差分確認の **4 つの安全装置** を常に併用する
