# アクセシビリティ基礎

## 解説

**アクセシビリティ（accessibility）** とは、年齢・障害の有無・利用環境にかかわらず、誰もが Web を利用できるようにする考え方です。
たとえば、目が見えにくい人はスクリーンリーダー（画面の内容を音声で読み上げるソフト）を使い、手が不自由な人はマウスを使わずキーボードだけで操作することがあります。

うれしいことに、**正しい HTML を書くことが、そのままアクセシビリティの大部分を満たす**ことにつながります。特別な技術より、これまで学んだ基本を丁寧に実践することが第一歩です。

---

## 1. 適切な要素を選ぶ

見た目が同じでも、意味に合った要素を選ぶことがアクセシビリティの土台です。

```html
<!-- 良い例: ボタンには button を使う -->
<button type="button">送信</button>

<!-- 避けたい例: 見た目だけボタンにした div -->
<div class="button">送信</div>
```

`<button>` は、最初からキーボードで操作でき、スクリーンリーダーにも「ボタン」と認識されます。
`<div>` でボタンの見た目を作っても、これらの機能は自動では付きません。

> [!TIP]
> 「リンクには `<a>`」「ボタンには `<button>`」「見出しには `<h1>`〜`<h6>`」というように、役割に合った要素を選ぶだけで、多くの配慮が自動的に行われます。

---

## 2. 画像に代替テキスト（`alt`）を付ける

画像が見えない人にも内容を伝えるため、`<img>` には `alt` を指定します。

```html
<!-- 内容を伝える画像 -->
<img src="chart.png" alt="2026年第1四半期の売上が前年比20%増加したことを示す棒グラフ" />

<!-- 装飾だけの画像は空にする -->
<img src="line-decoration.png" alt="" />
```

**ポイント**

- 情報を持つ画像には、その内容を具体的に書く。
- 装飾目的の画像は `alt=""` として読み上げから外す。
- 「画像」「写真」といった言葉は不要（スクリーンリーダーが自動で画像だと伝えるため）。

---

## 3. 見出しの階層を正しく保つ

見出し（`<h1>`〜`<h6>`）は、スクリーンリーダー利用者がページの構造を把握し、目的の場所へ素早く移動するための重要な手がかりです。

```html
<!-- 良い例: 階層を飛ばさない -->
<h1>料理ブログ</h1>
  <h2>和食</h2>
    <h3>味噌汁の作り方</h3>
  <h2>洋食</h2>

<!-- 避けたい例: h2 を飛ばして h3 に -->
<h1>料理ブログ</h1>
  <h3>味噌汁の作り方</h3>
```

> [!WARNING]
> 見出しレベルを「文字の大きさ」で選ぶのは誤りです。大きさは CSS で調整し、見出しレベルは**文書の構造**に従って選びましょう。

---

## 4. フォームにラベルを付ける

入力欄には必ず `<label>` を紐付けます。これにより、スクリーンリーダーが「何を入力する欄か」を読み上げられます。

```html
<label for="email">メールアドレス</label>
<input type="email" id="email" name="email" />
```

`placeholder`（薄く表示されるヒント）はラベルの代わりにはなりません。入力を始めると消えてしまい、読み上げ対応も不十分なためです。

---

## 5. キーボードだけで操作できるようにする

マウスを使えない人のために、**すべての操作がキーボードだけで完結**できることが重要です。

- `Tab` キーでリンクや入力欄を順番に移動できる。
- `Enter` や `Space` でリンク・ボタンを実行できる。

`<a>`・`<button>`・`<input>` などの標準要素を使っていれば、これらは**自動的に機能します**。
逆に `<div>` で自作したボタンは、キーボードでは操作できないことがあります。これも「適切な要素を選ぶ」ことの大切さにつながります。

> [!NOTE]
> 自分のページを `Tab` キーだけで操作してみると、キーボード利用者の体験を簡単に確認できます。すべてのリンクやボタンにたどり着けるか試してみましょう。

---

## 6. WAI-ARIA で意味を補う（`aria-label` など）

標準のタグだけでは意味が足りない場合に、**WAI-ARIA（ウェイ・アリア）** という仕組みで補足情報を追加できます。
代表的なのが、要素にラベルを与える `aria-label` 属性です。

```html
<!-- アイコンだけのボタンに、読み上げ用のラベルを付ける -->
<button type="button" aria-label="メニューを開く">☰</button>

<!-- 検索フォームに役割を伝える -->
<nav aria-label="メインナビゲーション">
  <a href="/">ホーム</a>
  <a href="/about">概要</a>
</nav>
```

`☰` のようなアイコンだけのボタンは、そのままでは何のボタンか伝わりません。
`aria-label="メニューを開く"` を付けると、スクリーンリーダーが「メニューを開く ボタン」と読み上げてくれます。

> [!IMPORTANT]
> WAI-ARIA は「標準の HTML で表現できないときの補助」です。`<button>` で済むものを `<div role="button">` で作るより、まず**適切な標準タグを使う**ことが最優先です。ARIA は最後の手段と考えましょう。

---

## まとめ

- アクセシビリティは「誰もが Web を使えるようにする」考え方。正しい HTML がその土台になる。
- 役割に合った標準要素（`<a>`・`<button>`・見出しなど）を選ぶ。
- 画像には適切な `alt`、装飾画像は `alt=""`。
- 見出し階層は飛ばさず、文書構造に従って使う。
- フォームの入力欄には必ず `<label>` を紐付ける。
- すべての操作がキーボードだけでできるようにする。
- 標準タグで足りないときだけ、`aria-label` などの WAI-ARIA で補う。
