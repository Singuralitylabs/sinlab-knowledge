# ターミナルとシェルとは

## 解説

「ターミナル」「シェル」「コマンドライン」「プロンプト」――よく一緒に使われますが、それぞれ少しずつ意味が違います。最初に整理しておきましょう。

### ターミナル・シェル・プロンプトの違い

| 用語 | 役割 | たとえると |
|------|------|-----------|
| ターミナル（端末） | 文字を入力・表示する**画面（アプリ）** | 電話機本体 |
| シェル | 入力されたコマンドを**解釈して実行するプログラム** | 通話相手・交換手 |
| プロンプト | 入力待ちを示す**記号**（`$` や `%`） | 「どうぞ」の合図 |

つまり、あなたが**ターミナル**というアプリに文字を打つと、その文字を**シェル**が受け取って解釈し、コンピュータに実行させます。実行が終わると再び**プロンプト**が表示され、次の入力を待ちます。

### シェルにはいくつか種類がある

シェルにはいくつかの種類があり、代表的なのが **bash**（バッシュ）と **zsh**（ズィーシェル）です。

- **macOS**：現在の標準は **zsh**（プロンプトは `%`）
- **Linux**：多くのディストリビューションで **bash**（プロンプトは `$`）
- **Windows**：標準は PowerShell だが、**Git Bash** を使えば bash が使える

基本的なコマンド（`cd`・`ls`・`mkdir` など）は bash でも zsh でも共通なので、まずは違いを気にせず進めて大丈夫です。

> [!NOTE]
> **Windows をお使いの方へ**
> Windows 標準の **PowerShell** や **コマンドプロンプト** は、コマンド名や挙動が本モジュールの解説と異なります。Git をインストールすると一緒に入る **Git Bash**、または **WSL** を使うと、本文と同じコマンドがそのまま使えます。検索エンジンで「Git Bash 起動方法」などと調べて、Git Bash を開いて進めることをおすすめします。

## コマンドの構造

ターミナルに打ち込む「コマンド」は、次の3つの部品からできています。

```text
ls   -l   /Users/taro
↑    ↑    ↑
コマンド オプション 引数
```

| 部品 | 役割 | 例 |
|------|------|-----|
| コマンド | 何をするか | `ls`（一覧表示） |
| オプション | どう動かすか（`-` で始まる） | `-l`（詳細表示）、`-a`（隠しファイルも） |
| 引数 | 何に対して行うか | `/Users/taro`（対象のパス） |

オプションと引数は省略できることも多く、`ls` だけでも動きます。オプションは `-la` のようにまとめて書けるほか、`--all` のように長い形式（ロングオプション）もあります。

## コマンドサンプル

```bash
# ターミナルを開いたら、まずはこの3つを試してみる

pwd          # いまどこにいるか（現在地）を表示
ls           # 現在地にあるファイル・フォルダの一覧
ls -la       # 隠しファイルも含めて詳細表示

whoami       # ログイン中のユーザー名を表示
date         # 現在の日時を表示
```

### ターミナルの開き方

| OS | 開き方 |
|----|--------|
| macOS | `Command + Space` で Spotlight を開き「ターミナル」と入力 / アプリケーション › ユーティリティ › ターミナル.app |
| Windows | Git をインストール後、スタートメニューで「Git Bash」を検索して起動 |
| Linux | `Ctrl + Alt + T`（多くの環境） |
| VS Code 共通 | メニューの ターミナル › 新しいターミナル、または `` Ctrl + ` `` |

## 実行結果

```text
$ pwd
/Users/taro

$ whoami
taro

$ date
2025年 6月 1日 日曜日 10時30分00秒 JST

$ ls
Applications  Desktop  Documents  Downloads  projects
```

プロンプト（`$` や `%`）の手前には、ユーザー名やホスト名、現在地などが表示されることもあります（環境によって見た目は異なります）。

## よくある間違い

### 1. プロンプトの記号まで打ってしまう

```bash
# ❌ 解説に書かれている $ や % は「プロンプト」なので打たない
$ pwd

# ✅ 打つのは $ の後ろの部分だけ
pwd
```

本やサイトのコマンド例にある先頭の `$` / `%` は「ここからがコマンドですよ」という目印です。実際に打つのはその後ろだけです。

### 2. 大文字・小文字を区別していない

```bash
# ❌ LS は別物として扱われ、コマンドが見つからない
LS

# ✅ コマンドは基本的に小文字
ls
```

ターミナルのコマンドは大文字・小文字を厳密に区別します。`ls` と `LS` は別物です。

### 3. 日本語入力（全角）のまま打っている

全角スペースや全角記号はコマンドとして認識されません。コマンドを打つときは**半角英数の入力モード**になっているか確認しましょう。

## 実用例

### コマンドが見つからないときの確認

```bash
# 打ったコマンドが「command not found」と言われたら…
ls --version    # そのコマンドが使えるか・バージョンを確認
which ls        # そのコマンドの実体がどこにあるかを表示
```

### 直前の操作をクリアして画面を整える

```bash
clear           # 画面表示をクリア（Ctrl + L でも同じ）
```

長く作業して画面がごちゃごちゃしてきたら `clear` で一度スッキリさせると見やすくなります。

## 実習

### 課題1：3つの基本コマンドを試す

1. ターミナル（Windows なら Git Bash）を開いてください
2. `pwd`・`ls`・`whoami` をそれぞれ実行し、何が表示されるか確認してください
3. `ls -la` を実行し、`ls` だけのときと表示がどう変わるか比べてください

### 課題2：コマンドの構造を意識する

次のコマンドについて、どれがコマンド・オプション・引数か答えてみましょう。

1. `ls -l Documents`
2. `mkdir my-project`
3. `cd ~`

### 課題3：自分の環境のシェルを調べる

1. `echo $SHELL` を実行してください
2. 表示された結果（`/bin/zsh` や `/bin/bash` など）から、自分が使っているシェルが何か確認してください
