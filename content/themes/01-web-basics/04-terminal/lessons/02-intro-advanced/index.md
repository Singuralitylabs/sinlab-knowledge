# ターミナルの応用テクニック

## はじめに

基礎編では、ファイルやフォルダを「作る・移動する・消す」操作を学びました。応用編では、コマンド同士を**組み合わせて**、より強力な作業を行う方法を学びます。

その鍵になるのが「**標準入出力**」という考え方です。

ターミナルのコマンドは、たいてい次のような形をしています。

```text
入力（標準入力 / stdin）→ [ コマンド ] → 出力（標準出力 / stdout）
                                       ↘ エラー出力（stderr）
```

- **標準入力（stdin）**：コマンドが受け取るデータ
- **標準出力（stdout）**：コマンドが吐き出す結果
- **標準エラー出力（stderr）**：エラーメッセージ（結果とは別の流れ）

ふだんは、入力はキーボード、出力は画面に流れています。この「流れ」を**横取りして、ファイルに保存したり、別のコマンドへ渡したり**できるのが、応用編の中心テーマです。

> [!NOTE]
> **Windows をお使いの方へ**
> 応用編も bash / zsh を前提にしています。Windows の場合は **Git Bash** または **WSL** を使うと、本文のコマンド（`>`・`|`・`grep`・`find` など）がそのまま動きます。

## 出力を保存する・つなぐ

画面に流れる出力を、ファイルに書き出したり（**リダイレクト**）、別のコマンドへ渡したり（**パイプ**）できます。

```bash
ls > files.txt          # ls の結果を画面ではなくファイルへ保存
ls | less               # ls の結果を less に渡してスクロール表示
```

`>` は「出力をファイルへ向ける」、`|` は「出力を次のコマンドへ流す」――この2つを覚えるだけで、できることが一気に広がります。

## 探す・加工する

ファイルが増えてくると、「あの文字列を含むファイルはどこ？」「あの名前のファイルはどこ？」を探したくなります。`grep` は**中身**を、`find` は**ファイルそのもの**を探すコマンドです。

```bash
grep "TODO" *.js        # .js ファイルの中から TODO を含む行を探す
find . -name "*.md"     # 現在地以下から .md ファイルを探す
```

::detail{slug="grep"}

::detail{slug="find"}

探すだけでなく、見つけたテキストを**加工**したり、見つけたファイル群を**まとめて処理**したりもできます。`sed`・`awk` は置換や列の抽出といったテキスト処理を、`xargs` は検索結果を別コマンドの引数として渡す橋渡しを担います。

```bash
sed 's/cat/dog/g' a.txt          # テキストを一括置換
awk '{ print $1 }' data.txt       # 1列目だけ取り出す
find . -name "*.tmp" | xargs rm   # 見つけたファイルをまとめて削除
```

## ファイルの権限

`Permission denied`（権限がありません）というエラーは、ファイルの**権限（パーミッション）**の仕組みによるものです。`chmod` でこの権限を変更すれば、スクリプトを実行可能にしたり、秘密情報を保護したりできます。

```bash
chmod +x script.sh      # スクリプトに実行権限を付ける
chmod 600 secret.txt    # 所有者だけが読み書きできるようにする
```

## 環境を整える

最後に、ターミナルを自分好みに整える方法です。**環境変数**（特に `PATH`）の仕組みを知ると「なぜこのコマンドが使えるのか」が分かり、**エイリアス**や**設定ファイル**を使えば、よく打つコマンドを短縮して毎回の手間を減らせます。

```bash
echo $PATH              # コマンドの探索先（PATH）を確認
alias gs="git status"   # gs と打つだけで git status が動くようにする
```

::detail{slug="env-and-path"}

::detail{slug="alias-and-config"}

ホームディレクトリ（`~`）には、これらの設定が `.zshrc`・`.gitconfig`・`.ssh/`・`.claude/` といった**隠しファイル（ドットファイル）**として保存されています。どのファイルが何の設定なのかを把握しておくと、トラブル時にも迷いません。

```bash
ls -a ~                 # ホームの隠しファイルも含めて一覧表示
```

## 応用コマンドまとめ

| 記号・コマンド | 説明 | 使用例 |
|----------------|------|--------|
| `>` | 出力をファイルへ（上書き） | `ls > files.txt` |
| `>>` | 出力をファイルへ（追記） | `echo done >> log.txt` |
| `2>` | エラー出力をファイルへ | `cmd 2> error.txt` |
| `\|` | 出力を次のコマンドへ渡す | `ls \| grep .md` |
| `grep` | 文字列を含む行を検索 | `grep -rn "TODO" src` |
| `find` | ファイル・フォルダを検索 | `find . -name "*.js"` |
| `sed` | テキストを置換・抽出 | `sed 's/a/b/g' f.txt` |
| `awk` | 列単位で抽出・集計 | `awk '{ print $1 }' f.txt` |
| `xargs` | 出力をコマンドの引数に渡す | `find . -name "*.tmp" \| xargs rm` |
| `chmod` | ファイルの権限を変更 | `chmod +x script.sh` |
| `echo` | 文字列・変数を表示 | `echo $PATH` |
| `export` | 環境変数を設定 | `export NODE_ENV=production` |
| `alias` | コマンドの別名を定義 | `alias ll="ls -la"` |
| `which` | コマンドの実体の場所を表示 | `which node` |

## まとめ

応用編では、コマンドを組み合わせる技を学びました。

中心にあるのは「**標準入出力**」という考え方です。コマンドの出力は、画面に流すだけでなく、`>` でファイルに保存したり、`|` で別のコマンドに渡したりできます。`grep` / `find` で探し、`sed` / `awk` で加工し、`xargs` でまとめて処理する。さらに `chmod` で権限を整え、環境変数やエイリアスで自分の環境を整えれば、ターミナルはぐっと使いやすくなります。

これらは一度に覚える必要はありません。「ログを保存したい」「あの文字列を探したい・置き換えたい」と思ったときに、この記事に戻ってきて使い方を確認すれば十分です。
