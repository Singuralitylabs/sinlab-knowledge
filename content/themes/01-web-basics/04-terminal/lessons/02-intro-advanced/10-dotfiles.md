# ホームディレクトリの設定ファイル（ドットファイル）

## 解説

ホームディレクトリ（`~`）で `ls -a` を実行すると、`.` で始まる見慣れないファイルやフォルダがたくさん表示されます。これらは **ドットファイル（dotfiles）** と呼ばれ、各種ツールが設定を保存しておく場所です。

`.` で始まるファイルは「**隠しファイル**」として、通常の `ls` やファインダー／エクスプローラーでは表示されません。設定ファイルのように「ふだんは触らないが、消えると困るもの」を、うっかり操作しないよう隠してあるのです。

これらの中身を理解しておくと、「シェルの設定はどこ？」「SSH 鍵はどこ？」と迷わなくなり、トラブル時の対処もしやすくなります。

---

## コマンドサンプル

```bash
# ホームに移動して隠しファイルも含めて一覧表示
cd ~
ls -a

# ドットファイルだけを一覧する
ls -a ~ | grep '^\.'

# 設定ファイルの中身を確認する
cat ~/.zshrc
cat ~/.gitconfig

# 隠しフォルダの中を見る
ls -la ~/.ssh
```

## 主な設定ファイル・フォルダ

ホームディレクトリでよく見かける、**操作する可能性のある**代表的なものです。

### シェル関連

| 名前 | 内容 | 触る場面 |
|------|------|----------|
| `.zshrc` | zsh（macOS 標準）の設定。エイリアス・PATH・環境変数 | エイリアス追加、PATH 設定 |
| `.bashrc` | bash の設定（同上） | bash 利用時の設定 |
| `.zprofile` / `.bash_profile` / `.profile` | ログイン時に読まれる設定 | PATH などログイン時の初期化 |

> シェルの設定ファイルの編集方法は、応用編「エイリアスとシェル設定ファイル」で詳しく解説しています。

### 開発ツール関連

| 名前 | 内容 | 触る場面 |
|------|------|----------|
| `.gitconfig` | Git のグローバル設定（ユーザー名・メール・エイリアス） | `git config --global` の保存先 |
| `.ssh/` | SSH の鍵と接続設定が入る**フォルダ** | GitHub 連携、サーバ接続 |
| `.claude/` | Claude Code の設定（`settings.json`、グローバル `CLAUDE.md`、スキル等） | AI 開発ツールの設定 |
| `.npmrc` | npm の設定（レジストリ・認証トークン） | パッケージ公開・社内レジストリ利用 |
| `.config/` | 多くのツールが設定を置く共通フォルダ | アプリごとの設定 |
| `.vimrc` | Vim の設定 | Vim のカスタマイズ |

### `.ssh/` フォルダの中身（よく触る）

| ファイル | 内容 |
|----------|------|
| `.ssh/id_ed25519` / `id_rsa` | **秘密鍵**（絶対に他人に渡さない） |
| `.ssh/id_ed25519.pub` | **公開鍵**（GitHub などに登録する側） |
| `.ssh/config` | 接続先ごとのホスト設定 |
| `.ssh/known_hosts` | 接続したことのあるサーバの記録 |

### キャッシュ・データ（基本は触らない）

| 名前 | 内容 |
|------|------|
| `.cache/` | 一時キャッシュ |
| `.local/` | ユーザー個人のプログラム・データ |
| `.DS_Store` | macOS がフォルダ表示情報を保存するファイル（設定ではない。Git では `.gitignore` 対象） |

> [!CAUTION]
> ドットファイル・隠しフォルダは「見えない」だけで、**普通のファイルと同じように削除・編集できてしまいます**。とくに `.ssh/`（鍵を失うとサーバや GitHub に接続できなくなる）や `.zshrc`（壊すとシェルが正しく起動しなくなる）は要注意です。編集前に `cp ~/.zshrc ~/.zshrc.bak` のようにバックアップを取り、`rm -rf ~/.*` のようなワイルドカード削除は絶対に避けてください。

## 実行結果

```text
$ cd ~
$ ls -a
.              .config         .splatter
..             .gitconfig      .zprofile
.cache         .ssh            .zsh_history
.claude        .vimrc          .zshrc
.DS_Store      Documents       projects

$ cat ~/.gitconfig
[user]
	name = Taro Yamada
	email = taro@example.com
[alias]
	st = status

$ ls -la ~/.ssh
total 24
-rw-------  1 taro  staff  411  6  1 09:00 id_ed25519
-rw-r--r--  1 taro  staff  100  6  1 09:00 id_ed25519.pub
-rw-r--r--  1 taro  staff  220  6  1 09:00 known_hosts
```

## よくある間違い

### 1. 隠しファイルが見えず「無い」と思い込む

```bash
ls ~          # ❌ .zshrc などは表示されない
ls -a ~       # ✅ 隠しファイルも表示される
```

設定ファイルが見当たらないときは、まず `-a` を付けて確認しましょう。

### 2. 秘密鍵をうっかり共有・コミットしてしまう

```bash
# ❌ .ssh の秘密鍵や .npmrc の認証トークンを Git にコミットするのは厳禁
git add .

# ✅ 秘密情報は .gitignore で除外し、公開鍵（.pub）だけを共有する
```

`.ssh/id_ed25519`（秘密鍵）や、トークンを含む `.npmrc`・`.env` は**絶対に公開しない**でください。GitHub に登録するのは `.pub`（公開鍵）の方です。

### 3. 設定ファイルを壊してシェルが起動しなくなる

```bash
# .zshrc に誤った記述をすると、新しいターミナルでエラーが出る
# → バックアップから戻すか、誤った行を削除して source ~/.zshrc
cp ~/.zshrc.bak ~/.zshrc   # 事前にバックアップしておくと安心
```

## 実用例

### 自分の環境にどんな設定があるか棚卸しする

```bash
ls -a ~ | grep '^\.'        # ホームのドットファイルを一覧
cat ~/.gitconfig            # Git の設定を確認
cat ~/.zshrc                # シェルの設定を確認
```

### 新しい PC へ設定を引き継ぐ

開発者は `.zshrc` や `.gitconfig` などのドットファイルを Git リポジトリで管理し、新しい環境へ一括で持ち込む「**dotfiles 管理**」をよく行います（秘密鍵などの機密ファイルは含めないのが鉄則）。

## 実習

### 課題1：ホームのドットファイルを観察する

1. `cd ~` でホームに移動し、`ls -a` を実行してください
2. `.` で始まるファイル・フォルダをいくつか見つけ、それぞれが何の設定か本文の表で確認してください

### 課題2：中身を確認する

1. `cat ~/.gitconfig` で Git の設定を確認してください（無い場合は `git config --global user.name "名前"` で作成）
2. `ls -la ~/.ssh` で SSH フォルダの中身を確認してください（鍵があれば `id_*` と `*.pub` のペアを探す）

### 課題3：安全に扱う意識を持つ

1. 「公開してよいファイル（例：`.ssh/id_ed25519.pub`）」と「絶対に公開してはいけないファイル（例：`.ssh/id_ed25519`）」を区別して挙げてみましょう
2. `.zshrc` を編集する前に、`cp ~/.zshrc ~/.zshrc.bak` でバックアップを取る練習をしてください
