# Source Control パネルの読み方

## 解説

**Source Control（ソース管理）パネル** は VS Code に組み込まれた Git の GUI クライアントです。アクティビティバーの分岐アイコンから開き、ここを起点に変更の確認・ステージング・コミット・プッシュまでを行います。

ターミナルで `git status` を打つ代わりに、変更ファイル一覧と各ファイルの状態をひと目で把握できます。

---

## 開き方

| 操作 | macOS | Windows / Linux |
|------|-------|-----------------|
| Source Control パネルを開く | `Cmd + Shift + G` | `Ctrl + Shift + G` |

アクティビティバーの **分岐アイコン** をクリックしても同じです。バッジ数字は「未コミットの変更ファイル数」を表します。

## パネルの構成

上から順に次のブロックが並びます。

| ブロック | 内容 |
|---------|------|
| **コミットメッセージ入力欄** | コミット前にメッセージを書く欄。`Cmd/Ctrl + Enter` でコミット |
| **コミットボタン（✓）** | メッセージ欄の下にあり、押すとコミット実行 |
| **Merge Changes（マージの変更）** | コンフリクトが発生したファイル（マージ中のみ表示） |
| **Staged Changes（ステージング済みの変更）** | `git add` 済みのファイル |
| **Changes（変更）** | まだステージされていない変更 |

各ファイル行の右側にはマウスオーバーで **`+`（ステージ）/ `−`（アンステージ）/ `↩`（変更を破棄）** などのアイコンが現れます。

---

## ファイルバッジの読み方

ファイル名の右に表示されるアルファベット 1 文字が、そのファイルの状態を示します。

| バッジ | 意味 |
|--------|------|
| **M**（Modified）| 既存ファイルが変更されている |
| **U**（Untracked）| 新規ファイル（Git の管理下になっていない） |
| **A**（Added）| ステージに追加済みの新規ファイル |
| **D**（Deleted）| 削除されたファイル |
| **R**（Renamed）| リネームされたファイル |

エクスプローラー側のファイル名にも同じバッジが付くので、ツリーを眺めるだけでも変更の所在が把握できます。

> **コンフリクト中のファイル** は `Changes` リストではなく、Source Control パネル上部に独立して現れる **`Merge Changes`（マージの変更）** セクションに分類されます。専用バッジが付くわけではなく、セクション位置で区別する仕組みです。

---

## ヘッダのアイコン群

パネル右上には次のアイコンが並びます。

| アイコン | 機能 |
|---------|------|
| **↻**（リフレッシュ） | リモートの状態を再取得 |
| **…**（メニュー） | Pull / Push / Fetch / Stash などの操作群 |
| **▼**（ビュー切替） | ツリー表示とリスト表示の切替、グループ化方法の変更 |

`...` メニューは「コマンドパレットを開かずに Git コマンドを呼び出す入口」として頻用します。

---

## ありがちなつまずき

- 「変更したのに Source Control に出てこない」 → ワークスペースが Git リポジトリではない可能性。リポジトリのルートで `git init` するか、フォルダを開き直す
- 「バッジ `U` のファイルがツリーに大量に出る」 → `.gitignore` に追加すべきファイル（`node_modules/`、ビルド成果物など）が漏れている
- 「変更件数のバッジ数字とファイル数が合わない」 → サブモジュールやマージ中の状態が混ざっている可能性
