# ステージングとコミット

## 解説

VS Code の Source Control（ソース管理）パネルでは、ステージング・コミット・変更の破棄をすべて GUI で行えます。CLI と比べた最大の利点は **行単位のステージング（hunk staging）** が直感的にできることです。

---

## ステージング

ステージング = `git add` 相当の操作。`Changes`（変更）リストから `Staged Changes`（ステージング済みの変更）に移動させます。

| 操作 | やり方 |
|------|--------|
| ファイル個別をステージ | ファイル行右の **`+`** アイコンをクリック |
| すべてをまとめてステージ | `Changes` 見出し右の **`+`** をクリック |
| ステージ解除（アンステージ） | `Staged Changes` 内のファイル右の **`−`** アイコン |

### ハンクステージング（変更の一部だけをステージ）

VS Code の GUI が特に強い領域です。ファイルを開いた状態でガターに表示される変更マーカー（左の縦バー）をクリックすると **「変更を確認」ホバー** が現れ、ハンク単位（連続する変更ブロック単位）でステージできます。

具体的な手順:

1. Source Control の `Changes` のファイルをクリックして diff ビューを開く
2. ガター（行番号の左）にある **変更マーカー** をクリック
3. 表示されるホバーから **`Stage Change`**（変更をステージング）または **`Stage Selected Ranges`**（選択した範囲をステージング）を選ぶ

行単位でさらに細かく分けたい場合は、diff ビュー上で行を選択してから右クリック ›  `Stage Selected Ranges`。「コミットを論理的に分けたい時」「同じファイル内の異なる目的の変更を別コミットにしたい時」に使います。

---

## 変更の取り消し（Discard Changes）

| 操作 | やり方 |
|------|--------|
| ファイル単位で破棄 | ファイル右の **`↩`** アイコン |
| すべて破棄 | `Changes` 見出し右の **`↩`** |
| ハンク / 行単位で破棄 | diff ビューのガター › **`Revert Change`**（変更を元に戻す）または `Revert Selected Ranges`（選択した範囲を元に戻す） |

> **注意**：破棄した変更は **OS のゴミ箱にも入らず即座に消える** ことが多いです。重要な変更は先にコミット、または `git stash`（CLI）で退避してから破棄します。

---

## コミット

1. パネル上部の **メッセージ入力欄** にコミットメッセージを書く
2. メッセージ欄の下の **✓（チェック）ボタン** を押す、または `Cmd + Enter` / `Ctrl + Enter`

`Staged Changes` が空の状態でコミットしようとすると **「ステージされた変更がありません。すべての変更をステージしてコミットしますか？」** と聞かれます。「はい」を選ぶと自動的に全変更をステージしてからコミットします（CLI の `git commit -a` 相当）。

![コミットメッセージ入力欄と ✓ チェックボタン](/content-assets/01-web-basics/03-vscode/images/43-commit.png)

### コミットメッセージのコツ

- 1 行目（タイトル）を 50 文字程度に収める
- 1 行目の後に空行を入れて本文を書く（必要に応じて）
- 「何を変えたか」より「なぜ変えたか」を書く

メッセージ欄は普通のエディタなので改行 `Enter` も使えます（コミット実行は `Cmd/Ctrl + Enter`）。

---

## Sync Changes（プッシュ + プル）

コミット後、コミットボタンの位置が **`Sync Changes`**（変更の同期）に変わります。これを押すと `git pull` → `git push` が一括で走ります。

`...` メニューから個別に `Pull`（プル）/ `Push`（プッシュ）/ `Fetch`（フェッチ）を実行することも可能です。

---

## ありがちなつまずき

- 「ステージしてもコミットボタンが反応しない」 → メッセージが空。何か入力すれば押せる
- 「`Cmd/Ctrl + Enter` で改行されてしまう」 → カーソルがメッセージ欄の中にあるか確認。フォーカスが別の場所だとコミットされない
- 「ステージしたのに `Changes` から消えない」 → 同じファイルで「ステージした分」と「ステージしていない分」が分かれている可能性。`Staged Changes` 側にも同名ファイルがあるか確認
- 「コミット履歴を後から修正したい」 → コマンド `Git: Commit (Amend)`（Git: コミット (修正)）で直前のコミットを修正できる（既にプッシュ済みの場合は注意）
