# 差分表示とマージコンフリクト

## 解説

VS Code の差分ビュー（diff view）は、変更前と変更後を **色付きで並べて** 比較できる機能です。コンフリクト発生時はインラインボタンで一発解決でき、CLI で手動編集するより安全に進められます。

---

## 差分ビューの開き方

Source Control（ソース管理）パネルの **ファイル名をクリック** すると、diff ビューが開きます。同様にエクスプローラーで右クリック › `Open Changes`（変更を開く）でも開けます。

![サイドバイサイド表示の diff ビュー：左に変更前、右に変更後](/content-assets/01-web-basics/03-vscode/images/44-diff.png)

### 表示モードの切替

差分ビュー右上のアイコンで切り替えられます。

| モード | 説明 |
|--------|------|
| **Side-by-side**（既定） | 左に変更前、右に変更後を並べて表示 |
| **Inline** | 1 つのバッファに削除行（赤）と追加行（緑）を縦に並べて表示 |

設定 `diffEditor.renderSideBySide` で既定値を変更できます。狭い画面では Inline、広い画面では Side-by-side が見やすいです。

### 色の意味

| 色 | 意味 |
|----|------|
| 赤背景の行 / `-` | 削除された行 |
| 緑背景の行 / `+` | 追加された行 |
| グレーアウト | 変更なしの周辺コンテキスト |

---

## ガターの変更マーカー

通常のエディタでファイルを開いているときも、行番号の左に Git の変更マーカーが表示されます。

| 色 / 形 | 意味 |
|---------|------|
| 緑の縦バー | 追加された行 |
| 青の縦バー | 変更された行 |
| 赤い三角（行間） | 削除された行（その位置で行が消えている） |

マーカーをクリックすると **インラインで変更内容のホバー** が表示され、`Stage Change`（変更をステージ）/ `Revert Change`（変更を取り消し）/ `Show Previous Change`（前の変更へ移動）などの操作ができます。

---

## マージの実行

VS Code 上でブランチをマージする手順は次の通りです。

1. マージ先のブランチに切り替える（例：`main` に checkout）
2. コマンドパレット（`Cmd/Ctrl + Shift + P`）を開く
3. **`Git: Merge Branch...`** を選択
4. 一覧からマージ元ブランチを選ぶ（例：`feature/login`）

衝突がなければそのままマージコミットが作られます。衝突があれば、続く節の手順で解決します。

> **CLI 派の人へ**：もちろん統合ターミナルで `git merge feature/login` を打っても結果は同じです。GUI を使う最大の利点は、衝突発生後に次節のインラインボタンで解決を進められることです。

---

## マージコンフリクトの解決

マージや pull で衝突が発生すると、対象ファイルが特殊な **コンフリクトビュー** で開き、Source Control パネルにも `Merge Changes`（マージの変更）リストとして現れます。

衝突箇所には次の標準マーカーが入ります。

```
<<<<<<< HEAD
あなたの変更（現在のブランチ）
=======
取り込もうとしている変更（マージ元）
>>>>>>> feature/login
```

VS Code はこれを認識し、衝突箇所の上に **インラインボタン** を表示します。

| ボタン | 動作 |
|--------|------|
| **Accept Current Change（現在の変更を取り込む）** | `HEAD`（現在のブランチ）の内容を採用 |
| **Accept Incoming Change（入力側の変更を取り込む）** | マージ元ブランチの内容を採用 |
| **Accept Both Changes（両方の変更を取り込む）** | 両方の内容を残す（手動調整が必要なことが多い） |
| **Compare Changes（変更の比較）** | 両者の差分を別ビューで開く |

![コンフリクト箇所の上に並ぶ Accept Current / Incoming / Both Changes / Compare Changes ボタン](/content-assets/01-web-basics/03-vscode/images/45-conflict.png)

### 解決後の手順

1. すべての衝突箇所で選択を済ませる（`<<<<<<<` などのマーカーが残っていないことを確認）
2. ファイルを保存
3. Source Control パネルで `Merge Changes` から `+` でステージ
4. コミットメッセージを入力してコミット（マージコミットは VS Code が自動でメッセージ案を入れることもあります）

### 3-way マージビュー

`Compare Changes` を押すと、**Current（HEAD）/ Incoming（マージ元）/ Result（最終結果）** の 3 ペイン UI が開き、行ごとにどちらを採用するか選べます。複雑な衝突ではこちらの方が見通しが良いです。

---

## ありがちなつまずき

- 「Accept したのに `<<<<<<<` が残ってコミットできない」 → 衝突マーカーは複数箇所に入ることがある。ファイル内検索（`Cmd/Ctrl + F`）で `<<<<<<<` を検索して全箇所を解決
- 「diff ビューで編集できない」 → 左側（変更前）は読み取り専用。右側（変更後）を編集する
- 「色付けが崩れて見える」 → カラーテーマや拡張機能の干渉。`Default Dark Modern` などの標準テーマで再確認
- 「マージを途中でやめたい」 → コマンド `Git: Abort Merge`（Git: マージの中止）で取り消せる（マージ前の状態に戻る）
