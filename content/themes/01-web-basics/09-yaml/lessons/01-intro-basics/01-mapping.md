# マッピングとスカラー値の書き方

## 解説

**マッピング**（Mapping）は、`キー: 値` のペアを並べたものです。JSONのオブジェクト、プログラミング言語の辞書（ハッシュ・連想配列）に相当します。

```text
キー1: 値1        ← キーと値をコロン : で結ぶ（: の後ろに半角スペース必須）
キー2: 値2        ← ペアは1行に1つ。カンマは不要
# コメント         ← # から行末まではコメント
```

JSONと比べると、`{}`・キーのダブルクォート・カンマが不要になっています。

```text
JSON:  { "name": "Taro", "age": 25 }

YAML:  name: Taro
       age: 25
```

### スカラー値（単一の値）の型

マッピングの値として書く1つの値を **スカラー** と呼びます。YAMLでは書き方から型が自動的に判定されます。

| 型 | 書き方の例 | 備考 |
|----|-----------|------|
| **文字列** | `Tokyo`, `"Tokyo"`, `'Tokyo'` | クォートは省略可 |
| **数値** | `25`, `-5`, `3.14` | クォートで囲むと文字列になる |
| **真偽値** | `true`, `false` | 小文字で書くのが推奨 |
| **null** | `null`, `~`, 値を空にする | 「値なし」を表す |

### クォートが必要な場面

基本的に文字列はクォート不要ですが、次のような値は **クォートで囲んで文字列であることを明示** します。

| 場面 | 例 | 理由 |
|------|----|----|
| 数値に見える文字列 | `zip: "0600001"`, `version: "1.10"` | `0600001` は先頭の0が消えた数値（古いパーサーでは8進数）に、`1.10` は数値 `1.1` になる |
| `: ` や `#` を含む | `title: "注意: 重要"` | `: ` がキーの区切り、` #` がコメントと解釈される |
| 記号で始まる | `pattern: "*.md"`, `"@scope/pkg"` | `*`・`&`・`@` などは特別な意味を持つ |
| 真偽値に見える文字列 | `answer: "yes"`, `country: "NO"` | 古いYAML 1.1 のパーサーでは `yes`/`no`/`on`/`off` が真偽値になる |

> [!NOTE]
> ダブルクォート `"..."` の中では `\n`（改行）などのエスケープが使えます。シングルクォート `'...'` の中は書いたままの文字列として扱われます（`'` 自体を書きたいときだけ `''` と2つ重ねます）。迷ったらダブルクォートを使いましょう。

## サンプル

### 基本的なマッピング

```yaml
# ユーザー情報
id: 101
username: suzuki_taro
isStudent: false
location: Tokyo
zip: "0600001"    # 数値ではなく文字列として扱う（先頭の0を残す）
note: null
```

### 複数行の文字列

長い文章は `|`（改行を保持）や `>`（改行をスペースに変換）を使って複数行で書けます。

```yaml
# 改行をそのまま保持する
message: |
  こんにちは。
  YAMLの学習を始めましょう。

# 改行をスペースにつなげて1行にする
summary: >
  この文章は
  1行につながります。
```

`>` でつないだ行の間には、日本語の文章でも半角スペースが1つ入ります（上の例は `この文章は 1行につながります。` になります）。また `|`・`>` のどちらも、最後の行の末尾の改行は残ります。

## よくある間違い

### 1. コロンの後ろにスペースがない

```text
❌ name:Taro
✅ name: Taro
```

`name:Taro` は「`name:Taro` という1つの文字列」と解釈され、マッピングになりません。

### 2. 同じキーを2回書いている

```text
❌ name: Taro
   age: 25
   name: Hanako

✅ name: Hanako
   age: 25
```

キーの重複はエラーになるか、ツールによっては後の値で黙って上書きされます。

### 3. 値にコロン＋スペースや ` #` が含まれている

```text
❌ title: 注意: 重要なお知らせ    ← 「: 」が2つありエラーになる
❌ memo: 予定 #後で確認          ← 「#後で確認」がコメント扱いになる

✅ title: "注意: 重要なお知らせ"
✅ memo: "予定 #後で確認"
```

なお `url: https://example.com/#top` のように、`:` の直後にスペースがない・`#` の直前にスペースがない場合は、クォートなしでも文字列として正しく読み込まれます。

## 実用例

### 設定値の型に注意する

アプリの設定で `version: 1.10` と書くと、数値 `1.1` として読み込まれ、意図したバージョンと違う値になってしまいます。同じように `phone: 09012345678` と書くと、先頭の `0` が消えた数値 `9012345678` になります。**バージョン番号・郵便番号・電話番号** など「数字だけど計算に使わない値」は、クォートで囲んで文字列にしておくのが安全です。

```yaml
appVersion: "1.10"
nodeVersion: "24"
phone: "09012345678"
```

## 実習

### 課題1

次のYAMLには3つの問題があります。すべて見つけて直してください。

```text
name:Hanako
version: 2.10
title: お知らせ: 明日は休講
```

解答例：

```yaml
name: Hanako
version: "2.10"
title: "お知らせ: 明日は休講"
```

### 課題2

次のJSONを、同じ意味のYAMLに書き換えてください。

```json
{ "city": "Osaka", "population": 2750000, "isCapital": false, "mayor": null }
```

解答例：

```yaml
city: Osaka
population: 2750000
isCapital: false
mayor: null
```
