# JSONの基本構造と書き方のルール

## 解説

JSONのデータは、**キー（Key）と値（Value）のペア** を `{}` で囲んだ「オブジェクト」が基本単位です。

```text
{                         ← オブジェクトの開始
  "キー1": 値1,           ← キーと値をコロン : で結ぶ
  "キー2": 値2            ← ペア同士はカンマ , で区切る（最後は付けない）
}                         ← オブジェクトの終了
```

ファイル全体（またはAPIのレスポンス全体）は、1つのオブジェクト `{...}` か1つの配列 `[...]` で表すのが一般的です。

### 書き方のルール

JSONはプログラムが機械的に解析するため、書き方のルールが厳格です。1文字でも違反するとパースエラーになり、データ全体が読み込めなくなります。

| ルール | 内容 |
|--------|------|
| キーはダブルクォート | キーは必ず `"` で囲む |
| 文字列もダブルクォート | 文字列の値も `"` で囲む（シングルクォート `'` は不可） |
| 末尾カンマ禁止 | 最後の要素の後ろにカンマを付けない |
| コメント不可 | `//` や `/* */` のコメントは書けない |
| 使える値は6種類 | 文字列・数値・真偽値・配列・オブジェクト・null のみ |

> [!NOTE]
> JavaScriptのオブジェクトリテラルとJSONは見た目が似ていますが、別物です。JavaScriptではキーのクォート省略・シングルクォート・末尾カンマ・コメントが許されますが、JSONではすべてエラーになります。

## サンプル

### 正しいJSONの例

```json
{
  "id": 101,
  "username": "suzuki_taro",
  "isStudent": false,
  "skills": ["HTML", "CSS", "JavaScript"],
  "profile": {
    "age": 25,
    "location": "Tokyo"
  },
  "note": null
}
```

## よくある間違い

### 1. キーをクォートで囲んでいない・シングルクォートを使っている

```text
❌ { name: "Taro" }
❌ { 'name': 'Taro' }

✅ { "name": "Taro" }
```

### 2. 末尾にカンマを付けている

```text
❌ {
     "name": "Taro",
     "age": 25,
   }

✅ {
     "name": "Taro",
     "age": 25
   }
```

要素を並べ替えたり削除したりしたときに、最後の要素にカンマが残ってしまうミスがよく起こります。

### 3. コメントを書いている

```text
❌ {
     // ユーザー名
     "name": "Taro"
   }

✅ {
     "name": "Taro"
   }
```

> [!TIP]
> VS Codeの `settings.json` や `tsconfig.json` にはコメントが書けますが、これは **JSONC**（JSON with Comments）という拡張形式として扱われているためです。通常のJSON（APIのレスポンスや `package.json` など）ではコメントは使えません。

## 実用例

### 設定ファイルを手で編集する

`package.json` などの設定ファイルを手で書き換えたあと、ツールが「Unexpected token」のようなエラーを出す場合は、まず末尾カンマとクォートの付け忘れを疑いましょう。原因の大半はこの2つです。

## 実習

### 課題1

次のJSONには3つの誤りがあります。すべて見つけて正しいJSONに直してください。

```text
{
  name: "Hanako",
  'age': 22,
  "city": "Osaka",
}
```

解答例：

```json
{
  "name": "Hanako",
  "age": 22,
  "city": "Osaka"
}
```
