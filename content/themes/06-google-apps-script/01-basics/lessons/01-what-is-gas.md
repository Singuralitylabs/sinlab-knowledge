# GASとは何か（できることと制約）

Google Apps Script（GAS）は、Google Workspace（スプレッドシート、Gmail、ドライブ、カレンダーなど）を自動化・拡張するためのクラウドベースのスクリプト環境です。インフラの準備やサーバー構築が不要で、ブラウザがあれば誰でも即座にコードを実行できる手軽さから、業務効率化のツールとして広く普及しています。

しかし、GAS には一般的な Node.js や Python などのバックエンド環境とは異なる**強い制約**が存在します。この制約を理解せずに生成 AI にコードを書かせると、途中で止まるコードや実行できないスクリプトが生成されてしまいます。本ページでは、GAS でできることと、AI に伝えるべき前提条件となる制約を整理します。

## このページで学べること

- Google Apps Script の概要と、できることの全体像
- Google Workspace Core Service 化に伴う位置づけの変化
- 料金体系と無料枠（コンシューマーアカウントと Workspace アカウントの違い）
- **6 分実行制限・クォータ・同期 API・V8 ランタイム**という GAS 固有の制約
- 制約を「AI 開発のコンテキスト」として位置づける理由

## GAS でできること

GAS は JavaScript（ECMAScript 2020 準拠の V8 ランタイム）で記述し、Google のインフラ上で実行されます。最大の特徴は、Google Workspace の各種サービスを数行のコードで操作できる専用 API が最初から組み込まれている点です。

| 操作対象 | できることの例 | 主な組み込みサービス |
| --- | --- | --- |
| Google スプレッドシート | データの読み書き、セルの書式設定、グラフ作成、レポート自動生成 | `SpreadsheetApp` |
| Gmail | メール自動送信、下書き作成、受信メールの解析とラベル付け | `GmailApp` |
| Google ドライブ | ファイル・フォルダの作成、権限管理、PDF 変換 | `DriveApp` |
| Google カレンダー | 予定の一括登録、空き時間検索、リマインダー設定 | `CalendarApp` |
| Google フォーム | 回答の自動集計、確認メール送信 | `FormApp` |
| 外部 Web サービス | REST API の呼び出し、Webhook 受信、Slack や LINE への通知 | `UrlFetchApp` |

これらのサービスを組み合わせることで、「スプレッドシートの回答をトリガーにして集計し、Slack と Gmail に通知を送る」といった連携処理が追加のライブラリなしで完結します。

### Google Workspace Core Service 化

Apps Script は、2026 年夏に Google Workspace の **Core Service（コアサービス）** に正式昇格しました。これにより、Gmail や Google ドライブなどと同様に、エンタープライズ水準の SLA（サービス品質保証）、コンプライアンス（SOC、ISO 等）、Google Workspace テクニカルサポートの対象となりました。

組織内での利用においても、セキュリティポリシーやデータガバナンスの観点から安心して導入・運用できる環境が整っています。

## 料金体系と無料枠

GAS 自体には独立した課金体系が存在せず、**Google アカウントを持っていれば無料で利用可能**です。一般的なクラウドサービスのような「関数実行回数ごとの従量課金」や「サーバー維持費」は発生しません。

ただし、無制限にリソースを使えるわけではなく、Google サービス全体で「1 日あたりの割り当て（クォータ）」が設定されています。無料のコンシューマーアカウント（@gmail.com）と、有料の Google Workspace アカウントでは利用枠が異なります。

| 機能 / クォータ | コンシューマーアカウント（無料） | Google Workspace アカウント |
| --- | --- | --- |
| 1 回あたりの最長実行時間 | **6 分** / 実行 | **6 分** / 実行 |
| カスタム関数の実行時間 | 30 秒 / 実行 | 30 秒 / 実行 |
| アドオンの実行時間 | 30 秒 / 実行 | 30 秒 / 実行 |
| メール送信上限 | 100 通 / 日 | 1,500 通 / 日（プランにより最大 2,000） |
| トリガー総実行時間 | 90 分 / 日 | 6 時間 / 日 |
| URL Fetch 呼び出し | 20,000 回 / 日 | 100,000 回 / 日 |
| 同時実行数（ユーザーあたり） | 30 / ユーザー | 30 / ユーザー |

> [!NOTE]
> 上記のクォータは Google の仕様変更により改定される場合があります。最新の値は Google 公式ドキュメント「Quotas for Google Services」をご確認ください。

## AI 開発で必ず把握すべき 4 つの制約

生成 AI（Claude Code や ChatGPT など）に「GAS のコードを書いて」とだけ頼むと、Node.js などの標準的なサーバー環境のつもりでコードを出力してしまうことが多々あります。AI に適切な指示を与えるために、以下の 4 つの制約を把握しておく必要があります。

```text
[GAS の制約 4 つ]
1. 6 分間の実行時間上限   ─── 長時間バッチは途中停止する（分割処理が必要）
2. 同期 API 前提           ─── SpreadsheetApp 等は同期実行（async/await 不要）
3. V8 ランタイムの制限     ─── Node.js 組み込みモジュール（fs, path 等）は使えない
4. 各種クォータの上限     ─── ループ内で API を連打すると上限エラーになる
```

### 1. 6 分間の実行時間上限

GAS の関数は、**1 回の実行が 6 分（360 秒）を超えると強制終了（Timeout）** されます。これは Google Workspace の有料アカウントであっても一律 6 分です。

数千行〜数万行のスプレッドシートを一括処理しようとしたり、ループの中で 1 件ずつ外部 API を呼び出したりすると、簡単に 6 分の壁に衝突します。そのため、大量データを扱う場合は「バッチ処理でまとめて読み書きする」か、「トリガーと PropertiesService を使って中断・再開するステート管理」が必要になります。

### 2. 同期 API が前提であること

現代の JavaScript や TypeScript では、外部との通信やデータベース操作に `async` / `await` や `Promise` を使うのが一般的です。

しかし、GAS の組み込みサービス（`SpreadsheetApp`、`DriveApp`、`GmailApp`、`UrlFetchApp` など）は **基本的に同期処理（Synchronous）** で動作します。

```javascript
// GAS ではこれで同期的に取得できる（Promise ではない）
const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
const value = sheet.getRange("A1").getValue();

// UrlFetchApp もレスポンスが返るまで同期ブロックする
const response = UrlFetchApp.fetch("https://api.example.com/data");
const json = JSON.parse(response.getContentText());
```

生成 AI は放っておくと `await SpreadsheetApp...` や `await UrlFetchApp.fetch(...)` のような不要な非同期コードを書きがちです。GAS 固有の API は同期型であることを AI にあらかじめ伝える必要があります。

### 3. V8 ランタイムと Node.js の違い

GAS は Google の V8 エンジンを採用しているため、アロー関数、分割代入、クラス構文、オプショナルチェイニング（`?.`）などのモダンな JavaScript 構文をそのまま使えます。

しかし、**Node.js のランタイムではありません**。以下のものはブラウザ・GAS 環境には存在しません。

- Node.js 組み込みモジュール（`fs`、`path`、`crypto`、`http` など）
- グローバル変数 `process.env`（代わりに `PropertiesService` を使用）
- `npm` パッケージの直接インポート（バンドラを使わない場合）

### 4. クォータ制限と API 呼び出しのオーバーヘッド

スプレッドシートに対する `getValue()` や `setValue()` は、内部的に Google のサーバーへのネットワーク RPC を伴います。

そのため、1 行ずつループを回して `setValue()` を呼び出すと、実行速度が極端に低下し、1 日あたりの呼び出しクォータにも抵触しやすくなります。**「1 回でまとめて取得（`getValues()`）し、メモリ上で配列を処理して、1 回でまとめて書き込む（`setValues()`）」** バッチ処理が必須の定石です。

## なぜこの制約が生成 AI 活用で重要なのか

後続のモジュール 2「生成 AI で GAS を開発する」では、Claude Code 等のコーディングエージェントを使って GAS アプリケーションを開発するワークフローを学びます。

AI コーディングツールは非常に優秀ですが、**「動作環境が GAS であること」とその「固有の制約」をプロンプトやコンテキスト（CLAUDE.md 等）で指定しない限り、一般的な Node.js 開発の流儀でコードを組み立ててしまいます**。

- 実行時間が長引く設計を提案して 6 分制限で落ちる
- `async` / `await` や Node.js の `fs` モジュールを使ったコードを提案する
- スプレッドシートのセルを 1 つずつ書き込む非効率なループを生成する

これらの失敗を防ぐ第一歩が、開発者自身が GAS の特性と限界を理解し、AI に対する明確なガードレール（前提条件）として言語化できるようにすることです。

## まとめ

- **GAS の特徴**: Google Workspace サービスを直接操作できるクラウドベースの実行環境。無料枠で手軽に始められ、Core Service 化によりエンタープライズでの信頼性も向上。
- **4 つの主要な制約**:
  1. 1 回あたりの最長実行時間は 6 分
  2. 組み込みサービスは同期型（`async`/`await` 不要）
  3. V8 ランタイムであり、Node.js 独自モジュールは動作しない
  4. サービスごとに 1 日あたりのクォータ上限がある
- **生成 AI との向き合い方**: GAS の制約を正確に理解しておくことが、AI に誤ったコードを書かせず、効率的なスクリプトを生成させるための前提となります。
