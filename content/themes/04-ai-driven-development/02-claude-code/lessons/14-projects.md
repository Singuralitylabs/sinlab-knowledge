# Claude Code Projects

Claude Code で複数の作業を同時に進めようとすると、段取りはすべて自分の仕事になります。クラウドセッションを 1 本ずつ起動し、それぞれに同じ背景説明を書き、どれが終わったか・どれが返事を待っているかを見に行く――セッションの数が増えるほど、この「取りまとめ」の手間が膨らみます。

**Projects** は、この取りまとめを Claude に渡す機能です。**プロジェクトは 1 本の継続する会話** で、そこに仕事を投げると、Claude が **コーディネーター**（取りまとめ役）としてタスクごとに **スレッド** を起動し、進み具合を追跡します。各スレッドは独立したクラウドセッションとして並列に動き、パソコンを閉じても作業を続けます。リポジトリ・指示・メモリは全スレッドで共有されるため、一度伝えたルールはこれから起動する新しいスレッドすべてに届きます。

> [!NOTE]
> 本記事の内容は **2026 年 9 月時点** のものです。Projects は 2026 年 9 月 17 日に公開された **パブリックベータ** で、**Pro / Max プラン** のアカウントから **段階的にロールアウト** されています。最初の対象はクラウドセッションを使ったことがあり、claude.ai の chat や Cowork に既存のプロジェクトを持たないアカウントで、Team / Enterprise プランは未対応です。スレッドは現在クラウドでのみ動きます（ブログでは手元のマシンでの実行にも近く対応予定とされています）。[claude.ai/code](https://claude.ai/code) やデスクトップアプリの Code タブのサイドバーに **Projects** が表示されない場合は、まだ自分のアカウントに届いていません。[ウェイトリスト](https://claude.com/form/projects)に登録できます。UI の名称や上限値は今後変わる可能性があるため、利用時は[公式ドキュメント](https://code.claude.com/docs/en/claude-projects)も確認してください。

## このページで学べること

- 前提となるクラウドセッションと、ローカルセッションとの違い
- プロジェクトを構成する 4 つの要素（会話・スレッド・共有される文脈・Overview ペイン）
- サブエージェントや Agent Teams との違いと、Projects が向いている仕事
- プロジェクトの作り方と、GitHub 側で必要な準備
- 仕事の投げ方、プルリクエスト（PR）の扱い、Overview ペインの読み方
- プロジェクトメモリ・プロジェクト指示と `CLAUDE.md` の使い分け
- 料金・上限と、他の並列化機能との使い分け、よくあるつまずき

## 前提: クラウドセッションとは

Projects のスレッドは、すべて **クラウドセッション** です。クラウドセッションとは、自分のパソコンではなく **Anthropic が管理するクラウド上で動く Claude Code のセッション** のことです。ローカルセッション（ターミナルや IDE で動かす普段の Claude Code）との違いは次のとおりです。

| | ローカルセッション | クラウドセッション |
| --- | --- | --- |
| 実行場所 | 自分のパソコン | クラウド（既定は Anthropic 管理の環境） |
| パソコンを閉じたら | 止まる | **そのまま動き続ける** |
| コードの取得 | 手元のファイルをそのまま使う | GitHub からクローンする（`claude --cloud` では手元のリポジトリをアップロードする場合もある） |
| 手元のツール・DB・社内 VPN | 使える | 使えない（クラウド環境で許可したものだけ） |
| 開始できる場所 | ターミナル / IDE / デスクトップアプリ（**Local**） | Web（[claude.ai/code](https://claude.ai/code)）/ デスクトップアプリ（**Cloud**）/ モバイルアプリの **Code** タブ / `claude --cloud "タスク"` |
| 確認・操作 | そのマシンから | どの端末からでも（スマートフォン含む） |

クラウドセッション自体は Pro / Max / Team プランと、Enterprise の一部の席種で使えます。ターミナルから新しいクラウドセッションを作る `--cloud` や、クラウドの作業を手元に引き取る `--teleport` については、[高度な機能: CLI / Web / Desktop をまたいだ移動](/themes/04-ai-driven-development/02-claude-code/advanced#cli--web--desktop-をまたいだ移動)を参照してください。

## Projects の全体像

プロジェクトは、次の 4 つの要素で成り立っています。

| 要素 | 役割 |
| --- | --- |
| **プロジェクト会話**（コーディネーター） | 長く続く 1 本の会話。Claude が受け取った仕事を「その場で答える」「新しいスレッドにする」「既存スレッドに回す」に振り分け、起動したスレッドをすべて追跡する。見えるのはスレッドからの報告で、スレッドの一挙一動ではない |
| **スレッド**（ワーカー） | 実際に作業する独立したクラウドセッション。自分のブランチ・クローン・コンテキストウィンドウを持ち、必要に応じて PR を開き、終わると会話に報告する |
| **全スレッドが共有するもの** | プロジェクトのリポジトリとファイル、**プロジェクト指示**、**プロジェクトメモリ**／各リポジトリの `CLAUDE.md` と skills（リポジトリが 1 つなら permission rules と hooks も）／claude.ai アカウントのコネクタ／クラウド環境（ネットワーク・環境変数・API 認証情報・ツール） |
| **Overview ペイン** | 全スレッドの状態を一覧する画面。**Threads**（状態別の一覧）/ **Library**（追加したファイルとスレッドが作ったファイル）/ **Pull requests** / **Routines** のタブを持つ |

![Projects の構成図。あなたがプロジェクト会話に仕事を送ると、コーディネーターの Claude がその場で答えるかスレッドを起動する。各スレッドは独自のブランチと PR を持つクラウドセッションで、リポジトリ・プロジェクト指示・プロジェクトメモリ・コネクタ・クラウド環境を共有する。Overview ペインはスレッドを状態別に一覧する](/content-assets/04-ai-driven-development/02-claude-code/images/projects/project-structure.png)

> [!IMPORTANT]
> スレッドは **自分のパソコンにある Claude Code の設定を何も引き継ぎません**。手元にだけインストールした skills・MCP サーバー・プラグイン・コマンドラインツールは、スレッドからは見えません。skills はプロジェクトのリポジトリにコミットするか claude.ai アカウントで有効にし、プラグインは **Project settings > Plugins** で追加し、MCP は claude.ai のコネクタとして接続し、ツールはクラウド環境のセットアップスクリプトでインストールします。

## サブエージェントと何が違うのか

「Claude が作業を分担させる」という点では [サブエージェント](/themes/04-ai-driven-development/02-claude-code/agents) と似ていますが、単位も寿命もまったく別物です。

| | サブエージェント | Projects のスレッド |
| --- | --- | --- |
| 単位 | 1 つのセッションの中で働く下請け | 独立したクラウドセッション |
| 寿命 | 親セッションの中だけ（同じセッション内なら再開も可） | プロジェクトが続く限り（後から追加の指示も送れる） |
| 作業対象 | 親と同じ作業ディレクトリ（ワークツリーで分離する場合もある） | スレッド専用のクローンとブランチ |
| 成果物 | 親への要約 | PR・ブランチ・Library のファイル |
| 最初に受け取る文脈 | 親が書いた委任メッセージと `CLAUDE.md`（会話履歴は引き継がない。Explore / Plan は `CLAUDE.md` も読まない） | プロジェクト指示・メモリ・リポジトリ（`CLAUDE.md` を含む）・コネクタ・環境 |
| 動く場所 | ローカルでもクラウドでも | クラウドのみ |

なお、スレッドの中でさらにサブエージェントを使うことはできます。**Agent Teams** も「リードが複数のチームメイトを動かす」点で似ていますが、こちらは 1 つのタスクのためにチームを組み、**そのタスクが終われば解散** します。プロジェクトは目標がある限り、数日〜数週間にわたって続きます。

## どんな仕事に向いているか

公式ドキュメントは、**1 セッションより長く続き、次々とタスクが生まれる目標** があるときにプロジェクトを作るよう勧めています。典型は次の 4 類型です。

| 類型 | 例 |
| --- | --- |
| 複数リポジトリにまたがる 1 つの目標 | 「全サービスを新しい lint 設定に揃える」→ リポジトリごとにスレッドと PR ができる |
| 継続的にタスクが湧く領域 | 1 つのサービスのバグ報告・スタックトレース・レビュー依頼を届くたびに貼る。一度「覚えて」と伝えた落とし穴は次の修正に活きる |
| 1 セッションに収まらない構築・移行 | 「`docs/spec.md` の内容を実装して」「非推奨の ORM から移行して」→ 部分ごとのスレッドに分かれ、序盤の決定事項が後のスレッドに届く |
| コード以外のドキュメント作業 | 契約書のフォルダやサポートチケットのエクスポートをアップロードし、質問を重ねる。まとめは **Library** タブにファイルで届く |

一方、次の場合は別の手段のほうが適しています。

| こんな場合 | 代わりに使うもの |
| --- | --- |
| 1 セッションで終わる単発の作業（「不安定なテストを直して」） | クラウドセッションを自分で 1 本起動する |
| 手元でしか届かないツールやサービスが必要（ローカル DB・エミュレータ・VPN の内側の API） | ローカルセッション、または複数のローカルセッションを管理する **agent view** |
| 会話を伴わない定期実行（「毎週月曜に依存関係レポートを投稿」） | 単独の [Routine](/themes/04-ai-driven-development/02-claude-code/routines) |
| 複数人が Slack チャンネルで一緒に指示・操作したい | [Claude Tag](https://claude.com/docs/claude-tag/overview)（Team / Enterprise 向け） |

## プロジェクトを作る

プロジェクトは [claude.ai/code](https://claude.ai/code)、デスクトップアプリの Code タブ、Claude のモバイルアプリ（iOS / Android）で作成・利用できます。ブラウザとデスクトップアプリでは、**ゼロから作る** 方法と **既存のクラウドセッションから作る** 方法の 2 通りがあります。

### 前提チェック

| 項目 | 確認すること |
| --- | --- |
| プラン | Pro または Max で、サイドバーに **Projects** が表示されている |
| GitHub（コードを扱う場合） | コードが **github.com** にある（GitHub Enterprise Server・GitLab・Bitbucket は不可）／接続した GitHub アカウントに **push 権限** がある／**Claude GitHub App がリポジトリにインストール済み** |
| ネットワーク・認証情報・ツール | プロジェクトのクラウド環境で決まる。既定の環境は主要なパッケージレジストリに届くので、他のドメイン・シークレット・追加ツールが必要なときだけ設定する。MCP サーバーが必要なら [claude.ai のコネクタ](https://claude.ai/customize/connectors)で接続済みか確認する |

> [!WARNING]
> ターミナルの `/web-setup` で GitHub を接続した場合、そのトークンで普通のクラウドセッションはリポジトリにアクセスできますが、**プロジェクトのスレッドには足りません**。スレッドには Claude GitHub App のインストールが必須です。

### GitHub アクセスを設定する

GitHub の準備はプロジェクトごとではなく、基本的に 1 回で済みます。

1. **GitHub アカウントを Claude に接続する**。claude.ai/code を初めて使うなら、初回訪問時の案内に従います。
2. **[Claude GitHub App](https://github.com/apps/claude) をインストール** し、プロジェクトで使うリポジトリへのアクセスを与えます。組織のリポジトリは組織オーナーしかインストールを完了できず、オーナーでなければ GitHub からオーナーへ承認依頼が送られます。
3. **SAML SSO を強制している組織では**、GitHub を再接続してその組織に対して Claude アプリを承認します。承認するまで、その組織のプライベートリポジトリは一覧に出ません。

手順が足りない場合は **New project** ダイアログやプロジェクト画面が不足している手順を名指しし、設定場所へのリンクを出します。設定後、**Check again** が表示されていれば押して確認します。

### ゼロから作る（New project）

サイドバーの **Projects** → **New project** を選ぶと、ダイアログが開きます（ブラウザなら [claude.ai/code/projects/browse](https://claude.ai/code/projects/browse) からも開けます）。

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| **Name** | ✅ | プロジェクト一覧に表示される名前 |
| **Goal** | | 目指すことを 1 行で（例: 「API の p95 レイテンシを 200 ms 未満に保つ」）。Claude はこれに向けて動く。後から **Project settings > General** で追加できる |
| **Context** | | 対象の GitHub リポジトリと、スレッドに読ませたいファイル・フォルダ・Google Drive フォルダ。**Add** で 1 つずつ追加する |

**Create project** を押すと、プロジェクト会話が開きます。**初めてのプロジェクト** では、こちらがメッセージを送る前に Claude が自発的に 1 ターン動きます（このターンもプランの使用量を消費します）。リポジトリがあれば **何も変更せずに探索して次の一手を提案するスレッド** を 1 本起動したり、最近のクラウドセッションをもとに **Setup recommendations**（追加すべきリポジトリ・作るべき Routine・始められるスレッド）を提示したりします。推薦されたリポジトリと Routine は最初からすべてオンになっているので、不要なものをオフにしてから **Update setup** を押します。

> [!TIP]
> プロジェクトの範囲は「継続的に仕事を足していく 1 つの流れ」に絞るのがコツです。リポジトリも、関係しそうなものを全部ではなく **ほとんどのタスクが触る 1〜2 個** に絞り、残りはプロジェクト指示に「どこに何があるか」を書いておきます。スレッドは必要なときに自分でリポジトリを追加できます（そのスレッドだけに追加され、プロジェクトが使っているのと同じ GitHub オーナーのリポジトリに限られます）。

### 既存のクラウドセッションから作る

すでに作業中のクラウドセッションがある場合は、サイドバーのセッションメニューから次のどちらかを選びます。

| メニュー | 動き |
| --- | --- |
| **Continue as a project** | セッション名で新しいプロジェクトを作って開き、Claude がセッションを読んで **Setup recommendations** を提示する。元のセッションは一覧に残り、実行中ならそのまま動き続ける（両方を同時に動かしたくなければ自分で止める） |
| **Move to project** | セッションの作業を **既存のプロジェクト** に取り込む。プロジェクト会話に「このセッションを読んで続きを引き受けて」というメッセージが投稿され、以降はプロジェクトのスレッドで進む |

## 仕事を投げて結果を読む

仕事はすべてプロジェクト会話に送ります。1 件ずつでも、まとめてでも、思いついたメモでも構いません。Claude は送られたメッセージを次のように振り分けます。

- **ちょっとした質問** → たいてい会話の中でその場で答える
- **新しい作業** → 新しいスレッド、またはその領域を担当中の既存スレッドに回し、どちらにしたかを伝える
- **無関係な複数のタスク** → それぞれ別のスレッドにする

新しいスレッドは、メッセージの下に **カード**（タイトルと状態を表示した枠）として現れ、クリックすると中身を開けます。Claude がすぐに始めず、**Suggested threads** として提案だけすることもあり、矢印ボタンで個別に、一覧下のボタンでまとめて開始できます。スレッドの詳しい結果はスレッドの中にあり、作ったファイルは **Library** タブにも並びます。

### 最初のバッチを送る前にやること

いきなり大量の仕事を送る前に、次の 4 つを済ませておくと、最初のスレッドが期待どおりに返ってきやすくなります。

1. **プロジェクト指示を書く**（後述）。対象ブランチ・作業の確かめ方・事前承認が必要なことなど
2. **小さな仕事を 1 本だけ試す**。終わったらスレッドを開き、報告の仕方とブランチ上の作業を確認する
3. **モデルと effort を確認する**。新規プロジェクトはスレッドが Opus・高 effort で、最も速くプランを消費する設定になっている
4. **「提案してから始めて」「同時に動かすのは数本まで」と頼む**。何本か期待どおりに返ってきたら制限を外す

## PR の扱いと Overview ペイン

スレッドがコードを変更するとき、特に指示がなければ次のように動きます。

| 段階 | 既定の挙動 |
| --- | --- |
| ブランチ | リポジトリの **デフォルトブランチから新しいブランチ** を切って作業する |
| PR の作成 | 頼まれたときに開く。バグ修正などの具体的な変更なら自分から開くこともある |
| PR を開いた後 | 他のクラウドセッションの設定に関係なく **auto-fix を有効にして PR を見張る**。CI が落ちれば修正を push し、レビューコメントに対応し、チェックが通ってレビュー可能になったらスレッドで知らせる |

ブランチを push したり PR を開いたりしたスレッドのカードには、次の一手のボタンが表示されます。**Resolve conflicts** / **Fix CI** / **Address comments** / **Merge it** はその指示を自分からのメッセージとしてスレッドに送るボタン、**Review PR** は GitHub の PR を開くボタン、**Create PR** はブランチを push したまま止まっているスレッドから直接 PR を作るボタンです。PR を開くタイミングや起点のブランチを変えたい場合は、タスクかプロジェクト指示に書きます。

**Overview** ペインの **Threads** タブは、スレッドを 6 つの状態で分けて表示します。

| 状態 | 中身 |
| --- | --- |
| **Ready for review** | PR が開いていてレビュー待ち |
| **Waiting on you** | あなたの返答・承認を待っている、または失敗した |
| **Working** | 実行中 |
| **Landing** | PR が承認済み、またはマージキューに入っている |
| **Idle** | 作業を終え、何も待っていない |
| **Resolved** | 完了扱い。自分でメニューから付けるか、PR のマージなど最後の一手の後に Claude が付けるか、1 週間動きがないと自動で付く（メニューから再開可能） |

スレッドが返事を待っていると、ヘッダーの **Overview** ボタンにドットが付きます。デスクトップアプリでは、Claude が会話に投稿したとき・スレッドがエラーになったとき・入力が必要になったときに **デスクトップ通知** も届きます（ブラウザでは通知が出ないため、ドットで確認します）。

## プロジェクトに文脈を持たせる

一度設定すれば新しいスレッドすべてに届く「常設の文脈」は 3 種類あります。

| 文脈 | 中身 | 設定場所 |
| --- | --- | --- |
| **プロジェクトメモリ** | 要件・決定事項・落とし穴などを Claude がファイルとして残すメモ。各スレッドは起動時に索引ファイル `MEMORY.md` を読み、必要に応じて他のファイルを開く | 会話やスレッドで「覚えて」「忘れて」と頼む。**Project settings > Memory** で閲覧・編集・削除 |
| **プロジェクト指示** | 新しいスレッドとプロジェクト会話に毎回送られる文章。**16,000 文字まで** | **Project settings > Memory > Project instructions**、または Claude に変更を頼む |
| **リポジトリ・ファイル・環境** | 各スレッドがクローンするリポジトリ、`/mnt/project-files` 配下で読めるファイル、スレッドが動くクラウド環境 | **Project settings > Environment**、ファイルは **Overview** の **Library** タブの **Add** |

プロジェクトメモリは、[メモリとコンテキスト管理](/themes/04-ai-driven-development/02-claude-code/memory)で扱う **手元の自動メモリとは別物** です（どちらも `MEMORY.md` という索引を使いますが、保存場所も中身も独立しています）。また各リポジトリの `CLAUDE.md` とも別で、スレッドは起動時にクローンした `CLAUDE.md` もあわせて読みます。

| 書きたいこと | 置き場所 |
| --- | --- |
| そのリポジトリのビルドコマンド・コーディング規約 | リポジトリの `CLAUDE.md` |
| このプロジェクトで決まったこと・分かった落とし穴 | プロジェクトメモリ |
| 全スレッドに毎回厳密に守らせたいルール | プロジェクト指示 |

### プロジェクト指示の書き方

プロジェクト指示は、全スレッドが最初に受け取る「作業指示書」です。公式ドキュメントは次の 5 項目を含めるよう勧めています。

1. このプロジェクトは何のためにあるか
2. 作業場所（どのリポジトリか、どのブランチから始めるか、PR の命名）
3. 完了と言う前に、スレッドが自分の作業をどう確かめるか
4. 必要なものが見つからないときにどうするか
5. 事前にあなたの承認が必要なこと

公式のサンプルを日本語にすると、次のようになります。

```text
このプロジェクトは、payments-api リポジトリで決済 API の p95 レイテンシを
200 ms 未満に保つためのものです。プロファイリング、クエリとキャッシュの修正、
それに伴う依存関係の更新を扱います。

- main からブランチを切り、スレッドごとに draft PR を 1 つ開くこと。
- 完了と言う前に `make test` と `make lint` を実行し、結果の要約行を最後のメッセージに貼ること。
- 必要なもの（リポジトリ・シークレット・API・コネクタなど）に届かない場合は、
  最初のメッセージで何が足りないかを正確に書いて止まること。代用・モック・推測はしない。
- マージ、force push、CI 設定の変更は、スレッドで私に確認してから行うこと。
```

作業が始まった後にスレッドの間違いを正したら、**その訂正を「覚えて」とも伝えます**。プロジェクトメモリに入り、以降のスレッドが最初から知っている状態になります。

### リポジトリが 1 つか複数かで変わること

スレッドはプロジェクトの全リポジトリをクローンしますが、`.claude/settings.json` の扱いはリポジトリの数で変わります。

| 各リポジトリにあるもの | リポジトリ 1 つ | リポジトリ複数 |
| --- | --- | --- |
| `CLAUDE.md` | 起動時に読み込む | 全リポジトリから読み込む |
| `.claude/` 配下の skills・agents・commands | 読み込む | 全リポジトリから読み込む |
| `.claude/settings.json` で有効にしたプラグイン | 読み込まない（**Project settings > Plugins** で追加する） | 同左 |
| `.claude/settings.json` の permission rules・hooks・`env` | **適用される**（クラウドでは効かない一部の `env` を除く） | **適用されない** |

複数リポジトリのプロジェクトでは、常設のルールはプロジェクト指示に、環境変数はクラウド環境に置きます。

## モデル・effort・コンテキスト・調整

モデルと effort は **Project settings > General** で設定します。新規プロジェクトは **すべて Opus** で、**スレッドは high effort、プロジェクト会話（コーディネーター）は low effort** が既定です。

| 設定 | 対象 |
| --- | --- |
| **Thread model** / **Thread effort** | スレッド。特定のタスクだけ変えたいときはタスクの中で頼み、実行中のスレッドはそのスレッドのモデル選択で変える |
| **Coordinator model** / **Coordinator effort** | プロジェクト会話の Claude |

**コンテキストウィンドウはユーザーが管理しません。** スレッドは自動でコンパクト（要約圧縮）され、会話側は全履歴ではなく直近のメッセージ・直近のスレッド・プロジェクトメモリから動くため、プロジェクトが続く限り会話も続きます。絶対に落としてはいけない情報はプロジェクトメモリに入れておきます。

進め方は会話で自然言語で調整できます。

```text
スレッドを始める前に提案して、私の了承を待って
同時に動かすスレッドは最大 2 本にして
同じ領域の追加依頼は既存のスレッドを使い回して
計画を私が見るまで PR は開かないで
それはスレッドを立てずにここで答えて
```

Claude はこうした好みを自分でプロジェクトメモリに保存し、以降のスレッドでも従います。ただし **これは Claude が守ろうとする preference（好み）であって、強制される設定ではありません**。「最大 2 本」も厳密な上限にはならないため、文言どおりに全スレッドへ最初から適用したいルールはプロジェクト指示に書きます。

> [!IMPORTANT]
> スレッドは、モデルが対応していれば **auto モード** で動くため、大半のツール実行は確認なしで進みます。承認が必要になったときは **そのスレッドの中** に確認が表示され、スレッドはそこで答えるまで待ちます。プロジェクト会話で「進めて」と言っても届きません。**Overview** の **Waiting on you** からスレッドを開いて答えてください。

## 料金と上限

プロジェクトの利用は、他の Claude Code セッションと **同じプランの上限** から消費されます。複数のスレッドが同時に動くため、**単一のセッションより速く上限に近づきます**（特に Pro プランでは、プロジェクトを動かした日は早めに上限に達する前提で考えます）。

| 消費するもの | 内容 |
| --- | --- |
| 実行中のスレッド | それぞれが完全な 1 セッション。本数に固定の上限はなく、強制される上限は **全プロジェクト合計で 1 日 200 スレッド（新規）** |
| プロジェクト会話 | スレッドの報告を読み、次の手を決めるためにトークンを使う |
| PR を見張るスレッド | CI の失敗やレビューコメントが来るたびに起きて消費する。不要ならスレッドで「PR の見張りをやめて」と頼む |

実行中のスレッドも、見張り中の PR も、新しいメッセージもないプロジェクトは、放置していても消費しません（アーカイブしたプロジェクトも同様）。

> [!WARNING]
> スレッドがプランの上限（5 時間枠・週枠）に達すると、**自動で再試行を続け、枠がリセットされたら作業を再開します**。放置していた作業が、次の利用枠を黙って使い始めるということです。次の枠を使わせたくない場合は、スレッドで **Stop** を押すか、**Project settings > General** の **Pause** でプロジェクト全体を止めます。なお、Routine から起動したスレッドだけは待たずにエラーで止まります。

使用量は **Project settings > Usage** で、スレッド別・モデル別・会話分に分けて確認できます。減らすための主な方法は次の 3 つです。

| 方法 | 理由 |
| --- | --- |
| 新しい作業は、古い大きなスレッドを起こさず **新しいスレッドで** 頼む | キャッシュの有効期限（Pro / Max では 1 時間）を過ぎたスレッドは、再開時に会話全体を読み直すため |
| 最大のモデルが不要な作業では、**小さいモデルや低い effort** を選ぶ | スレッド・会話それぞれで設定できる |
| **同時に動かすスレッドを減らし**、小さな質問はその場で答えてもらう | 会話で頼むだけで調整できる |

## 他の並列化機能との使い分け

Claude Code には、複数の作業を同時に進める方式が 5 つあります。「並列に動くこと」自体はどれも同じで、違いは **誰が取りまとめるか** と **どこで動くか** です。

| 方式 | 誰が取りまとめるか | どこで動くか | 向いている場面 |
| --- | --- | --- | --- |
| **Subagents** | Claude（1 セッションの中で委任し、結果を回収） | 親セッションの中 | 検索結果やログで本筋の会話を埋めたくない脇道の作業 |
| **Agent view** | 自分（手渡して、あとで一覧で確認） | 自分のマシン | 独立した複数のタスクを渡し、必要なときだけ介入したい（研究プレビュー） |
| **Agent teams** | Claude（リードがチームメイトに割り当てて監督） | 自分のマシン、またはクラウドセッションの中 | 1 つのタスクを分割して同期させながら進めたい（実験的機能・既定で無効） |
| **Dynamic workflows** | スクリプト（計画をスクリプトが保持） | セッションの中で多数のサブエージェントを実行 | コードベース全体の監査・大規模な移行・結果の相互検証 |
| **Projects** | Claude（コーディネーター） | **クラウド** | 数日〜数週間にわたる多数のタスクを、マシンを止めても進めたい。一度説明して任せたい |

![Claude Code の並列化 5 方式（Subagents・Agent view・Agent teams・Dynamic workflows・Projects）を、取りまとめ役・動く場所・続く期間・向いている場面・提供状況で比較した図](/content-assets/04-ai-driven-development/02-claude-code/images/projects/parallel-approaches.png)

周辺機能との関係も整理しておきます。

| 機能 | Projects との関係 |
| --- | --- |
| **Worktree** | ローカルで並列セッションが同じファイルを上書きし合わないための仕組み。スレッドはそれぞれ専用のクローンとブランチで動くため **不要**。同じコードを触ったスレッド同士の衝突は、通常の PR と同じくマージコンフリクトとして解決する |
| **Routines** | プロジェクト内で定期的な仕事を頼むと、Claude がそのプロジェクトのスレッドとして動く Routine を作り、**Routines** タブに載せる。プロジェクト外で作った Routine はこれまでどおり単独で動く（[Routines とスケジュール実行](/themes/04-ai-driven-development/02-claude-code/routines)） |
| **Claude Tag** | Team / Enterprise 向けの Slack 上の Claude。チャンネルの誰もが指示でき、全員が見られる。プロジェクトは **自分専用** で、自分の GitHub アクセスとコネクタを使う |
| **claude.ai chat / Cowork の旧 Projects** | 会話と参考ファイルをまとめる **フォルダ型** の従来機能で、スレッドもコーディネーターもない。新しい Projects はこれを作り直したもので、新しい体験が届くまでは従来どおり動き、その後順次移行される予定（[Claude Cowork](/themes/04-ai-driven-development/02-claude-code/cowork)） |
| **CLI の `claude project` コマンド** | ディレクトリ単位のローカル状態を管理するコマンドで、Projects とは **無関係** |

## 注意点と落とし穴

> [!CAUTION]
> **スレッドのサンドボックスは、ターンの合間に一時停止します。** 再開できなかった場合、スレッドは新しいクローンから続きを始めるため、**コミットしていない変更は失われることがあります**。長いタスクでは「作業途中でもこまめに commit と push をして」と指示してください。

| 症状・制限 | 原因 | 対処 |
| --- | --- | --- |
| スレッドが止まって見える | Claude はスレッドの各ステップを会話に投稿しない。新しいスレッドはクラウド環境の準備から始まる | スレッドを開いてトランスクリプトを読む。承認待ちならそこで答える |
| 複数のスレッドが同じ誤った前提で動く・「blocked」で止まる | 個々のタスクではなく、プロジェクト設定の同じ穴が原因であることが多い | 「各スレッドについて、頼んだこと・前提にしたこと・届かなかったもの・待っていることを一覧にして」と会話で聞く → 誤ったスレッドは Resolved にする → プロジェクト指示か環境を **1 か所** 直す → 1 本試してから残りを新しいスレッドで送り直す |
| 「Claude hasn't responded」バナーが出る | Claude は動いているが、返信が会話に届いていない | バナーの **Restart Claude**（または **Project settings > General** の **Restart**）。書きかけの返信は失われるが、スレッドには影響しない |
| 「Couldn't start the session — Claude doesn't have GitHub access…」 | Claude GitHub App が未インストール・停止中・接続アカウントと未リンク | メッセージのボタン（**Install GitHub App** など）→ **Check again** |
| 「Unable to access your repository」 | クローンの失敗（GitHub が拒否・リポジトリ名の不一致・指定ブランチが存在しない） | リポジトリ名と起点ブランチを確認する |
| 「Claude can't access」（リポジトリ保存時） | App 未インストール、または App はあるが接続アカウントと未リンク | 前者はインストールリンク、後者は再接続リンクを使う |
| プロジェクトやスレッドをチームで共有できない | プロジェクトは **1 ユーザー専用**。スレッドのトランスクリプトにも共有オプションがない | 共同作業が必要なら PR やドキュメント経由で共有する。ベータ期間中は組織単位の管理機能もない |
| スレッドを別のプロジェクトへ移したり、単独のセッションとして切り出したりできない | スレッドは起動したプロジェクトに属する（**Move to project** はセッションをプロジェクトへ取り込む一方向のみ） | 最初から適切なプロジェクトでスレッドを起動する |
| 複数リポジトリのプロジェクトで permission rules や hooks が効かない | 複数リポジトリでは各リポジトリの `.claude/settings.json` が適用されない | ルールはプロジェクト指示、環境変数はクラウド環境に置く |
| CLI や Bedrock / Agent Platform / Foundry から使えない、ローカルセッションを入れられない | 仕様（Web・デスクトップ・モバイルのみ、スレッドは Anthropic がモデル提供元のクラウドセッション） | ローカルの並列作業は agent view などを使う |

## まとめ

- **Projects** は、1 本の継続する会話で Claude がコーディネーターとなり、並列のクラウドセッション（**スレッド**）を起動・追跡する機能。2026 年 9 月時点で Pro / Max 向けのパブリックベータ
- スレッドは独自のブランチ・クローン・コンテキストを持ち、**リポジトリ・プロジェクト指示・プロジェクトメモリ・コネクタ・クラウド環境** を共有する。手元の設定は引き継がない
- 前提は **github.com のリポジトリ・push 権限・Claude GitHub App のインストール**。`/web-setup` のトークンだけでは足りない
- コードを変えるスレッドは既定で **新ブランチ → PR → auto-fix で見張る**。状態は **Overview** の 6 分類で確認し、承認は **スレッドの中** で答える
- リポジトリ固有のルールは `CLAUDE.md`、プロジェクトの決定事項はプロジェクトメモリ、全スレッドに厳密に守らせたいルールはプロジェクト指示に置く
- 単一セッションより **速くプランを消費** し、上限到達後は自動で待って再開する。最初は小さく 1 本試し、同時本数とモデルを絞ってから広げる
